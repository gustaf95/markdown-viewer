# Markdown Viewer for Windows 요구사항 정의서

## 1. 프로젝트 개요

본 프로젝트는 Windows 환경에서 안정적으로 동작하는 데스크톱 Markdown Viewer를 개발하는 것을 목표로 한다. 사용자는 `.md`, `.markdown`, `.txt` 형식의 문서를 열어 한글, 영문, 코드 블록, 표, 이미지, 수식 등을 포함한 Markdown 문서를 정확하게 렌더링하여 확인할 수 있어야 한다.

실제 구현은 Claude Code를 사용하여 진행할 예정이므로, 본 README는 개발자가 바로 구현을 시작할 수 있도록 기능 요구사항, 기술 요구사항, UI 요구사항, 렌더링 요구사항, 테스트 기준을 정리한 문서이다.

---

## 2. 핵심 목표

- Windows에서 실행 가능한 Markdown Viewer 제공
- 한글 문서의 깨짐 없는 표시 지원
- Markdown 표준 문법 및 확장 문법 지원
- LaTeX 기반 수식 렌더링 지원
- 코드 블록 문법 강조 지원
- 로컬 이미지 표시 지원
- 사용자가 파일을 쉽게 열고 읽을 수 있는 간단한 UI 제공
- 향후 편집기 기능으로 확장 가능한 구조 확보

## 4. 권장 기술 스택

Claude Code가 구현할 때 다음 기술 스택 중 하나를 선택할 수 있다.

### 4.1 권장안: Electron 기반

| 구성 요소 | 권장 기술 |
|---|---|
| 데스크톱 프레임워크 | Electron |
| UI | HTML, CSS, JavaScript 또는 TypeScript |
| Markdown 파서 | markdown-it 또는 marked |
| 수식 렌더링 | KaTeX 또는 MathJax |
| 코드 하이라이팅 | highlight.js 또는 Shiki |
| 파일 처리 | Node.js fs API |
| 패키징 | electron-builder |

Electron은 Windows 데스크톱 앱 제작이 쉽고, Markdown 렌더링 생태계가 풍부하며, 수식·코드·이미지 표시를 웹 기술로 안정적으로 구현할 수 있다는 장점이 있다.

### 4.2 대안: Python 기반

| 구성 요소 | 권장 기술 |
|---|---|
| GUI | PySide6 또는 PyQt6 |
| Markdown 렌더링 | QWebEngineView + markdown-it/marked 번들 또는 Python markdown |
| 수식 렌더링 | KaTeX/MathJax HTML 삽입 |
| 패키징 | PyInstaller |

단, Python 기반은 WebEngine 포함 시 배포 파일 크기가 커질 수 있으므로 Electron을 우선 고려한다.

## 5. 주요 기능 요구사항

## 5.1 파일 열기

| ID | 요구사항 |
|---|---|
| F-001 | 사용자는 파일 열기 대화상자를 통해 Markdown 파일을 선택할 수 있어야 한다. |
| F-002 | 지원 확장자는 `.md`, `.markdown`, `.txt`를 기본으로 한다. |

| F-004 | 최근 열었던 파일 목록을 제공할 수 있어야 한다. |

## 5.2 Markdown 렌더링

| F-104 | 중첩 목록을 지원해야 한다. |
| F-105 | 인용문 `>`을 지원해야 한다. |

| F-107 | 링크 `[text](url)`를 지원해야 한다. |
| F-108 | 로컬 이미지 및 외부 이미지 링크를 표시해야 한다. |
| F-109 | GitHub Flavored Markdown, 특히 표 문법을 지원해야 한다. |

## 5.3 한글 지원

| ID | 요구사항 |
|---|---|
| F-201 | 한글 제목, 본문, 표, 코드 주석이 깨지지 않고 표시되어야 한다. |
| F-202 | 한글과 영문, 숫자, 수식이 혼합된 문서를 자연스럽게 표시해야 한다. |
| F-203 | 기본 글꼴은 Windows에서 가독성이 좋은 한글 글꼴을 사용해야 한다. 예: `맑은 고딕`, `Noto Sans KR`, `Pretendard` |
| F-204 | 줄바꿈, 문단 간격, 목록 들여쓰기가 한글 문서에서도 어색하지 않아야 한다. |
| F-205 | CP949 또는 EUC-KR 계열 파일을 열 경우 가능한 범위에서 자동 변환하거나 사용자에게 인코딩 선택 옵션을 제공해야 한다. |

## 5.4 수식 렌더링

| ID | 요구사항 |
|---|---|
| F-301 | 인라인 수식 `$...$`을 지원해야 한다. |
| F-302 | 블록 수식 `$$...$$`을 지원해야 한다. |
| F-303 | LaTeX 기본 문법을 지원해야 한다. 예: 분수, 첨자, 적분, 행렬, 그리스 문자 |
| F-304 | 한글 본문 중간에 포함된 수식도 깨지지 않아야 한다. |
| F-305 | 수식 렌더링 실패 시 앱이 멈추지 않고 오류 위치를 표시하거나 원문을 보여줘야 한다. |
| F-306 | KaTeX 또는 MathJax 중 하나를 사용하되, 오프라인 실행을 위해 필요한 스크립트와 스타일은 앱에 포함해야 한다. |

### 수식 예시

```markdown
인라인 수식 예시: $E = mc^2$

$$
\int_{0}^{\infty} e^{-x^2} dx = \frac{\sqrt{\pi}}{2}
$$
```

## 11. 구현 세부 지침

## 11.1 Markdown 처리

- Markdown 파서는 `markdown-it` 사용을 권장한다.
- 다음 플러그인을 검토한다.
  - `markdown-it-katex` 또는 `markdown-it-mathjax3`
  - `markdown-it-task-lists`
  - `markdown-it-anchor`
  - `markdown-it-footnote`
  - `markdown-it-container`
- HTML sanitize 처리를 반드시 적용한다.

## 11.2 수식 처리

- 빠른 렌더링과 오프라인 동작을 우선하면 KaTeX를 권장한다.
- MathJax는 호환성이 더 넓지만 상대적으로 무거울 수 있다.
- 기본 구현은 KaTeX로 시작하고, 필요 시 MathJax 옵션을 추가한다.

## 11.3 파일 인코딩 처리

- 우선 UTF-8로 읽는다.
- UTF-8 디코딩 실패 또는 깨짐 의심 시 CP949 디코딩을 시도한다.
- Node.js에서는 `iconv-lite` 사용을 권장한다.
- 사용자가 직접 인코딩을 선택할 수 있는 옵션을 제공하면 좋다.

## 11.4 로컬 이미지 경로 처리

- Markdown 파일의 위치를 기준으로 상대 경로를 해석한다.
- 예: `docs/sample.md` 내부의 `![img](images/a.png)`는 `docs/images/a.png`로 해석한다.
- 보안을 위해 허용 범위를 명확히 관리한다.

## 11.5 Electron 보안 설정

Electron 사용 시 최소한 다음 설정을 적용한다.

```javascript
webPreferences: {
  nodeIntegration: false,
  contextIsolation: true,
  preload: path.join(__dirname, 'preload.js')
}
```

- renderer에서 직접 `fs` 접근 금지
- preload를 통해 제한된 API만 노출
- 외부 링크는 `shell.openExternal()`로 기본 브라우저에서 열기

## 17. 비고

- 본 프로젝트는 우선 Viewer 기능에 집중한다.
- Markdown 편집 기능은 1차 목표가 아니며, 향후 확장 기능으로 분리한다.
